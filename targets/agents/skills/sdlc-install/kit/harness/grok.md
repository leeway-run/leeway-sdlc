## Delegating to a named agent

Delegate to the custom subagent by name ("use the sdlc-implementer subagent to …"). Agents are `.grok/agents/<name>.md`. UNVERIFIED: the delegation tool's name. Every delegation starts a **fresh** agent, and its final message is what you gate.

## Governed-agent marker

governed-marker: required

The guards cannot yet tell a subagent's shell call from yours in xAI Grok Build (docs/targets/grok.md records what
its hooks send). So mark the window: immediately before each delegation, from the repo root,

    node .sdlc/kit/hooks/adapters/governed.mjs on <task-ref>

and as soon as the agent returns, **however it returns**,

    node .sdlc/kit/hooks/adapters/governed.mjs off <task-ref>

While the marker is live every shell call is judged as the subagent's, yours included, so never commit, push or
write to Leeway with it on. It expires on its own after two hours, so a crashed run cannot lock you out for longer.

## Wiring

sdlc-install writes these from `kit/wiring/grok/`, and sync-repo keeps them current:
- `.grok/hooks/leeway-sdlc.json`
- `.grok/agents/<agent>.md`

After writing them: Run `/hooks-trust` in Grok so it runs `.grok/hooks/leeway-sdlc.json`. Grok hooks fail open: a crashed or timed-out guard lets the command run.

## Permissions for an unattended run

run's allow-list goes in `~/.grok/config.toml` or the project's `.grok/` settings (permission rules).

## Installed version, update and restart

- **installed:** `grok inspect` (lists skills).
- **refresh the source:** nothing to refresh: the update command fetches the latest.
- **update:** `npx -y skills add leeway-run/leeway-sdlc/tree/main/targets/agents/skills -a grok --yes` again.
- **restart:** start a new Grok session.
- **commands:** user-invocable skills are `/<skill>`, for example `/sync-repo`.
