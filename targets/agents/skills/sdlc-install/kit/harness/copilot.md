## Delegating to a named agent

Delegate to the custom agent by name: in Copilot CLI the `task` tool with the agent `sdlc-implementer` (or ask "use the sdlc-implementer agent to …"); in VS Code, `runSubagent` with that agent. Agents are `.github/agents/<name>.agent.md`. Every delegation starts a **fresh** agent, and its final message is what you gate.

## Governed-agent marker

governed-marker: required

The guards cannot yet tell a subagent's shell call from yours in GitHub Copilot (CLI and VS Code agent mode) (docs/targets/copilot.md records what
its hooks send). So mark the window: immediately before each delegation, from the repo root,

    node .sdlc/kit/hooks/adapters/governed.mjs on <task-ref>

and as soon as the agent returns, **however it returns**,

    node .sdlc/kit/hooks/adapters/governed.mjs off <task-ref>

While the marker is live every shell call is judged as the subagent's, yours included, so never commit, push or
write to Leeway with it on. It expires on its own after two hours, so a crashed run cannot lock you out for longer.

## Wiring

sdlc-install writes these from `kit/wiring/copilot/`, and sync-repo keeps them current:
- `.github/hooks/leeway-sdlc.json`
- `.github/agents/<agent>.agent.md`

After writing them: Nothing to trust: Copilot runs `.github/hooks/*.json` from the repo. The Copilot cloud coding agent is not supported by this version.

## Permissions for an unattended run

run's allow-list goes in `.github/copilot/settings.json` (`permissions`), or `--allow-tool` flags for one run.

## Installed version, update and restart

- **installed:** `copilot plugin list`.
- **refresh the source:** `copilot plugin marketplace update` where it was installed from a marketplace; otherwise the install command again.
- **update:** `copilot plugin install leeway-run/leeway-sdlc:targets/agents` again (it replaces the installed version).
- **restart:** start a new Copilot session (VS Code: reload the window).
- **commands:** skills are invoked as `/<skill>`, for example `/sync-repo`.
