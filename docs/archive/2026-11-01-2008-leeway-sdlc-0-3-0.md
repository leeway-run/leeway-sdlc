## Decisions taken at plan time

1. **Where the "filing work" answer lives.** `.sdlc/leeway.md`, a new line `filing-work: plan-work` or
   `filing-work: manual`. `sync-repo` has always refused to write that file; it gains one narrow exception: a
   key of the binding that the repo's file lacks (`filing-work:` here, `friction-project:` in LWY-115) is asked
   for once and appended, and nothing else in the file is touched. `update` hands over to `sync-repo`, so it
   asks there and not twice.
2. **How the block varies.** The template gains one placeholder, `{{FILING_WORK_RULE}}`, filled with the rule
   paragraph for `plan-work` and with nothing (the line removed) for `manual`. `sync-repo` already compares the
   block "filled in as sdlc-install fills it", so it fills this placeholder from the binding too.
3. **Friction as a project.** The binding's `friction-collector: <ref>` becomes `friction-project: <project id>`.
   Proposed friction that the human accepts is filed as one `chore` issue per item in that project. A repo
   still carrying the old key keeps working: the skills read the old ref as "comment on this issue" until
   `sync-repo` migrates the key on the human's yes.
4. **The interview cap.** "At most eleven questions" rises to fit the new questions; each new one is asked only
   when detection found the divergence, so a clean repo sees no more questions than before.
5. **R12 does not apply.** These stories change the plugin's skills, not a Leeway feature a person uses through
   a surface, so no "is it an op?" escalation is raised.

## Verification

The lanes are CI's (`release.yml`): `node --test "plugin/hooks/*.test.mjs" "plugin/hooks/adapters/*.test.mjs"
"plugin/test/*.test.mjs" "scripts/*.test.mjs"`, `node scripts/build-targets.mjs --check`, and
`node .github/scripts/check-manifests.mjs`. Every task regenerates `targets/` with
`node scripts/build-targets.mjs` and stages it.

Not checked by this plan: a live install in a fresh repo, and a new agent session choosing plan-work on its own
(LWY-113's "Done when"). Both need a real agent session and a Leeway product; the release notes say they were not
run.
